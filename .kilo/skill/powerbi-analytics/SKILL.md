# Power BI Analytics — Линейные системы

## 1. Подключение к модели

### 1.1. Открытый Power BI Desktop (MCP)
Файл `.pbix` должен быть открыт в Power BI Desktop. Через MCP `powerbi-modeling-mcp` выполнить:

```
Connect to '[File Name]' in Power BI Desktop
```

(или промпт `ConnectToPowerBIDesktop`). MCP цепляется к локальному инстансу Analysis Services
(`localhost:<порт>/<guid>`), который Desktop поднимает при открытии файла.

### 1.2. Режимы запуска (kilo.json)
| Режим | Флаг | Когда |
|-------|------|-------|
| Только чтение (анализ) | `--readonly` | Аудит, scorecard, без изменений |
| Чтение + запись (дефолт) | нет флага | Докрутка мер/метрик, подтверждения перед изменением |
| Запись без подтверждений | `--skipconfirmation` | Только с бэкапом модели |

> ВНИМАНИЕ: MCP изменяет только **семантическую модель** (таблицы, колонки, меры, связи, RLS, TMDL),
> но не отчётные страницы/визуализации. Перед изменениями — бэкап модели.

## 2. Аудит модели

Последовательность проверок (по приоритету):

1. **Структура и связи**: однонаправленные фильтры, отсутствие bi-directional, неактивные связи,
   orphan-ключи, несоответствие кардинальности (1:* vs *:*).
2. **Naming**: консистентность префиксов мер (Measure/Calc), таблиц (Dim/Fact), колонок.
3. **DAX-аномалии**: `FAT`-выражения, `FILTER(ALL(...))` вместо `CALCULATE`, отсутствие `DIVIDE`
   вместо `/`, неявные преобразования, меры без FormatString/Description/DisplayFolder.
4. **Производительность**: авто-дата/время (Auto Date/Time), обрезка пустых колонок, неиспользуемые меры.
5. **Документация**: описание всех таблиц/мер, единый формат чисел, валюта RUB.

### Scorecard
Оценка 0–100 по семействам: моделирование, связи, производительность, naming, DAX, документация.

## 3. Докрутка DAX-мер

Общие паттерны для корпоративной аналитики «Линейные системы»:

```dax
-- Безопасное деление
Net Margin % = DIVIDE([Net Profit], [Net Revenue], 0)

-- Time intelligence (требует таблицы дат, связанной с Fact)
Sales LY = CALCULATE([Sales], SAMEPERIODLASTYEAR('Date'[Date]))

-- Рабочие дни / производственные показатели
```

Принципы:
- `DIVIDE` вместо `/`; `SUMX` для агрегаций с фильтром строк; избегать `FILTER(ALL(...))`.
- Каждая мера: имя с префиксом, FormatString, Description, DisplayFolder.
- Не дублировать меры с одинаковой логикой — использовать связные меры.

## 4. Документирование модели

- Сгенерировать markdown по каждой таблице: колонки (типы), меры (DAX + бизнес-логика), связи.
- Зафиксировать lineage (откуда данные: 1С/Битрикс24/Excel → Power Query).
- Mermaid-диаграмма связей таблиц.

## 5. Ограничения и безопасность
- Метаданные модели могут уходить LLM-провайдеру — не выгружать чувствительные данные в лог.
- Работать сначала в `--readonly` для анализа, затем точечные изменения в readwrite.
- Отчётные страницы/макет через MCP не меняются — только семантическая модель.
